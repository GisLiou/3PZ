# 專案架構

## 1. 技術分工

| 層                         | 技術                                                | 負責                                            |
| -------------------------- | --------------------------------------------------- | ----------------------------------------------- |
| 介面（選單、清單、對話框） | React 18 + TypeScript                               | 一般畫面、表單                                  |
| 戰鬥、特效                 | DOM＋Web Animations API（直接操作元素，不經 React） | 拼圖盤面、戰鬥演出                              |
| 打包                       | Vite 8                                              | 網頁版 → GitHub Pages；`dist/` 同時給 Capacitor |
| 手機 App                   | Capacitor 8                                         | Android／iOS 外殼、實體返回鍵                   |
| 存檔                       | localStorage（每帳號一份，有版本遷移）              | 之後可接雲端                                    |

- 轉蛋等大量特效是否改用 PixiJS 待決定（`開發步驟.md`）；目前未安裝，需要時再加入。
- 開發環境：Node.js 22.12 以上（`package.json` 的 `volta` 固定為 22.23.4）。單元測試 Vitest 5、素材轉檔 sharp 0.35。
- 相依套件一律寫死版本；升級後要跑 `npm audit`（必須 0 個漏洞）、`npm test`、`npm run build`、`npm run check:mobile`。
- 電腦版：需要時再加 Electron 外殼，共用同一份 `dist/`。

## 2. 設計解析度

- 原版為 640 寬；高度在 960～1136 之間彈性（iPhone 4／5），超出部分上下留黑邊。
- 安全黑邊：整個遊戲的左右與下方各留一條細黑邊（`core/stage.ts` 的 `SAFE_MARGINS`，CSS 像素），畫面不貼齊螢幕邊緣，避免轉珠時觸發系統的邊緣手勢。
- 程式中所有座標、尺寸都用**設計單位**（640 寬）。CSS 以 `calc(var(--design-unit) * N)` 換算（程式裡寫 `designUnit(N)`），`--design-unit` 由 `core/stage/stage.ts` 依螢幕計算。
- `遊戲素材/UI等/界面/resources-auto` 的圖本身就是 640 設計尺寸：原圖 1px ＝ 1 設計單位，放上去不用縮放。

## 3. 資料夾（`game/`）

原則：**依功能分類，類別內再依檔案種類分資料夾**——畫面與元件（.tsx）放 `components/`、程式（.ts）放 `logic/`、樣式（.css）放 `styles/`；只有一種檔案的類別不再分。相關的小檔合成一個檔案；每個類別以 `index.ts` 對外匯出。演出時間（毫秒常數）寫在使用它的檔案裡。
**關卡＝資料**：部隊、合戰、敵人、勝利條件、背景音樂、教學步驟都寫在 `data/stages/<關卡>.json`（敵人、部隊可寫在共用的 `data/enemies.json`、`data/parties.json`）；新增關卡只要加 JSON，格式見 [`關卡格式.md`](關卡格式.md)。命名規則與新舊名稱對照見 [`命名規範.md`](命名規範.md)。

## 4.

### 教學（JSON 步驟）

教學一律寫成 JSON 步驟（戰鬥：關卡 JSON 的 `script`），由 `@ui` 的 `runTutorialSteps` 依序執行。遮罩（`TutorialOverlay`）是一張蓋住整個畫面的透明 modal：擋下所有操作、變暗，只留下「明亮的洞」與「可以操作的範圍」。

| 步驟                                                         | 作用                                                                                                                                                                                                                                    |
| ------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `{ "say": 台詞, "highlight"?: 元件 id 或 {x,y,w,h} }`        | 玲玲對話，點「確定」繼續；其他操作全部擋住                                                                                                                                                                                              |
| `{ "tap": 元件 id, "text"?: 說明 }`                          | 高亮該元件，只有那裡可以點（點擊照常生效），點了才繼續；高亮右邊有手指按下的提示與「タッチ!」（`"touchHint": false` 不顯示；戰鬥教學的位置寫在 `modules/battle/components/TutorialLayout.tsx`，可熱更新），有 `text` 才顯示玲玲與說明窗 |
| `{ "wait": 毫秒 }`、`{ "save": {…} }`、`{ "goto": 場景 id }` | 等待、寫入存檔、換場景                                                                                                                                                                                                                  |

遮罩參數（`say`、`tap` 共用）：`highlight` 可以是陣列（多個洞，例：轉珠指引時路徑經過的每一格）；`dim`（變暗程度，預設 0.5）、`dimArea`（變暗範圍，預設整個畫面）、`padding`（元件四周多留，預設 5）、`radius`（洞的圓角）、`touchable`（可以操作的範圍，`"highlight"`＝跟洞一樣）。

元件 id：戰鬥是敵人 id（例：`{ "tap": "zhouYu" }`＝只能點周瑜，點了就鎖定）或 `StandardBattleLayout` 的元件（`portraits`、`hpBar`、`menu`、`board`…）；其他畫面在元素加上 `data-tutorial-id="<id>"` 就能被指定。畫面自己的步驟（例：戰鬥的 `guidedMove`、`wave`）以 `handlers` 加入 `runTutorialSteps`，見 `TutorialMask.tsx`。

## 4. 規則

1. **模組只能往下依賴**：`modules` → `ui` → `core`；`core` 不可 import `modules`。三大類（starter、begin、battle）之間不互相 import，唯一例外是 `starter` → `begin`（見 `模組相依.md`）；需要溝通時由 `app/` 組合。跨類只能 import 對方的 `index.ts`（例：`@modules/begin`）；同一類裡面用相對路徑。
2. **畫面只用原版素材**；必須自製時放到 `自製素材/` 並記錄於 `自製素材/README.md`。
3. **動畫時間一律寫成毫秒常數**（名稱以 `Ms` 結尾），註明取自哪部影片、哪一禎（見 `docs/復刻分析/`）。戰鬥中消珠、連擊、攻擊的時間寫成 `fast(原版毫秒)`，整體速度由 `battleAssets.ts` 的 `BATTLE_ANIMATION_SPEED` 一處調整（1＝原版）。
4. **手機操作**：返回鍵是遊戲內返回、捲動用拖曳、按鈕用 pointer 事件，詳見 `docs/手機操作規範.md`；每次合併前跑 `npm run check:mobile`。
5. **語音不進安裝包**：網頁版放在 `voice/` 供下載；App 版建置時移除，下載來源由 `VITE_VOICE_BASE` 指定。
6. **命名**：依 [`命名規範.md`](命名規範.md)；本機儲存的 key 一律由 `core/saveStore.ts` 的 `storageKey()` 產生。
