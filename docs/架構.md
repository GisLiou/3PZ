# 專案架構

## 1. 技術分工

| 層 | 技術 | 負責 |
|---|---|---|
| 介面（選單、清單、對話框） | React 18 + TypeScript | 一般畫面、表單 |
| 戰鬥、特效 | DOM＋Web Animations API（直接操作元素，不經 React） | 拼圖盤面、戰鬥演出 |
| 打包 | Vite 8 | 網頁版 → GitHub Pages；`dist/` 同時給 Capacitor |
| 手機 App | Capacitor 8 | Android／iOS 外殼、實體返回鍵 |
| 存檔 | localStorage（每帳號一份，有版本遷移） | 之後可接雲端 |

- 轉蛋等大量特效是否改用 PixiJS 待決定（`開發步驟.md`）；目前未安裝，需要時再加入。
- 開發環境：Node.js 22.12 以上（`package.json` 的 `volta` 固定為 22.23.4）。單元測試 Vitest 5、素材轉檔 sharp 0.35。
- 相依套件一律寫死版本；升級後要跑 `npm audit`（必須 0 個漏洞）、`npm test`、`npm run build`、`npm run check:mobile`。
- 電腦版：需要時再加 Electron 外殼，共用同一份 `dist/`。

## 2. 設計解析度

- 原版為 640 寬；高度在 960～1136 之間彈性（iPhone 4／5），超出部分上下留黑邊。
- 程式中所有座標、尺寸都用**設計單位**（640 寬）。CSS 以 `calc(var(--design-unit) * N)` 換算（程式裡寫 `designUnit(N)`），`--design-unit` 由 `core/stage/stage.ts` 依螢幕計算。
- `遊戲素材/UI等/界面/resources-auto` 的圖本身就是 640 設計尺寸：原圖 1px ＝ 1 設計單位，放上去不用縮放。

## 3. 資料夾（`game/`）

原則：**一個功能由多個子部分組成時，子部分各自一個資料夾**；資料夾內的 `index.ts` 是對外的公開入口，其他模組只從入口 import。命名規則與新舊名稱對照見 [`命名規範.md`](命名規範.md)。

```
game/
├─ index.html                 視窗設定：禁止縮放、禁止整頁拖動
├─ vite.config.ts / tsconfig.json / capacitor.config.ts
├─ tools/
│  ├─ assets/                 素材處理
│  │  ├─ build-assets.mjs     遊戲素材 → public/（webp、mp3、manifest、voice-index）
│  │  ├─ slice-atlas.py       無座標圖集切圖 → src/data/atlas/*.json
│  │  └─ slice-font.py        點陣字切字 → src/data/font/*.json
│  ├─ checks/
│  │  └─ check-mobile.mjs     手機操作自動檢查
│  ├─ deploy/
│  │  └─ link-develop-assets.mjs  開發版素材：與正式版相同的指向正式版，不同的另存（分支與發布.md §5）
│  └─ replica/                復刻分析工具（逐禎截圖、場景索引、接觸表）
├─ public/                    （產生物，不進 git）assets/ bgm/ voice/
└─ src/
   ├─ main.tsx                進入點：手勢限制、返回鍵、掛載 App
   ├─ app/                    App 外殼、場景登記表（sceneRegistry.ts）、啟動場景、尚未復刻的佔位畫面
   ├─ core/                   與遊戲內容無關的基礎模組（可在別的遊戲重用）
   │  ├─ stage/       設計解析度與縮放
   │  ├─ navigation/  場景路由（堆疊）、返回鍵處理
   │  ├─ input/       拖曳捲動
   │  ├─ assets/      素材清單與預載、以原圖像素覆蓋（imagePatch）
   │  ├─ audio/       背景音樂／音效／語音
   │  ├─ storage/     存檔、版本遷移、本機儲存 key
   │  ├─ animation/   毫秒動畫工具
   │  └─ events/      事件匯流排
   ├─ ui/                     共用 UI 元件（全部由原版素材組成）
   │  ├─ components/  Sprite、NineSliceFrame、TextLabel、SpriteButton
   │  ├─ atlas/       圖集零件顯示與輪播
   │  └─ bitmapText/  點陣字
   ├─ data/                   資料表
   │  ├─ atlas/       圖集零件座標（檔名＝原版素材檔名）
   │  ├─ font/        點陣字切字座標（檔名＝原版字型檔名）
   │  └─ pieces/      小兵珠子的圖集、姿勢表、走路禎序
   └─ modules/                遊戲功能模組（每個功能一個資料夾）
      ├─ account/     帳號（信箱＋密碼）；providers/ 帳號提供者（本機、日後雲端）
      ├─ voicePack/   語音下載
      ├─ opening/     開場流程：scenes/（注意、標題、帳號、輸入名字）、components/（共用視窗、連線中）
      ├─ tutorial/    新手教學：starterSelection/、story/、battle1/、guide/
      └─ battle/      戰鬥
         ├─ board/      盤面規則（純邏輯，有測試）；recordings/ 錄影解碼的盤面
         ├─ boardView/  盤面畫面：拖曳、消除、補位、連擊字、小兵圖
         ├─ screen/     戰鬥畫面：BattleScreen 組合以下子部分
         │  ├─ scenery/   天空與透視地面

         │  ├─ party/     我方頭像、HP 條、傷害數字
```

## 4. 規則

1. **模組只能往下依賴**：`modules` → `ui` → `core`；`core` 不可 import `modules`。模組之間不互相 import，需要溝通時用 `core/events` 的事件，或由 `app/` 組合（例外見 `模組相依.md`）。跨模組只能 import 對方的 `index.ts`（例：`@modules/battle`）。
2. **畫面只用原版素材**；必須自製時放到 `自製素材/` 並記錄於 `自製素材/README.md`。
3. **動畫時間一律寫成毫秒常數**（名稱以 `Ms` 結尾），註明取自哪部影片、哪一禎（見 `docs/復刻分析/`）。
4. **手機操作**：返回鍵是遊戲內返回、捲動用拖曳、按鈕用 pointer 事件，詳見 `docs/手機操作規範.md`；每次合併前跑 `npm run check:mobile`。
5. **語音不進安裝包**：網頁版放在 `voice/` 供下載；App 版建置時移除，下載來源由 `VITE_VOICE_BASE` 指定。
6. **命名**：依 [`命名規範.md`](命名規範.md)；本機儲存的 key 一律由 `core/storage/storageKeys.ts` 產生。
