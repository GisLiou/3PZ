# 分支與發布

## 1. 原則

| 分支 | 用途 | 網址 | 誰可以改 |
|---|---|---|---|
| `main` | 正式版：可正常遊玩的版本 | `https://<GitHub 帳號>.github.io/<儲存庫名稱>/` | **不直接推送**；只接受 `develop`、`hotfix/*` 的 PR |
| `develop` | 開發版：所有開發都在這裡 | `https://<GitHub 帳號>.github.io/<儲存庫名稱>/develop/` | 直接推送，或由功能分支合併 |
| `hotfix/<名稱>` | 正式版的緊急修正（從 `main` 開） | — | 修正後 PR 到 `main` |
| `gh-pages` | 網站內容，由工作流程自動產生 | — | 不手動修改 |

1. **develop 的任何修改都不會影響 main 的遊戲**：
   - 程式碼：develop 的修改只有經過「發布」（§3，PR 審視後合併）才會進入 main。
   - 網站：main 只寫網站根目錄，develop 只寫 `/develop/`。開發版與正式版相同的素材直接讀取根目錄的檔案（只讀），不同的素材放在 `/develop/` 自己的資料夾，所以 develop 換了素材也不會蓋掉正式版的素材。
2. **參考資料（原版錄影）不進 git**：只放在自己電腦的 `參考資料/`，`.gitignore` 已排除（只追蹤說明檔 `參考資料/README.md`）。併入 main 的 PR 若含影片檔會被檢查擋下。

## 2. 第一次建立儲存庫

前置：`D:\3PZ` 已放入 `遊戲素材/`，`.github/workflows/` 已放入兩個工作流程檔（`deploy-pages.yml`、`checks.yml`）。`參考資料/` 的影片放不放都可以，不會被加入 git。

```powershell
cd D:\3PZ
git init -b main
git add .
git status          # 確認清單裡沒有 參考資料 的影片
git commit -m "初始版本"
git switch -c develop
git remote add origin https://github.com/<GitHub 帳號>/<儲存庫名稱>.git
git push -u origin main
git push -u origin develop
```

- `遊戲素材/` 約 1 GB，一次推送若失敗，可分幾次 commit、推送（例：先 `遊戲素材/BG`、`BGM`、`UI等`，再其餘）。

### GitHub 設定

1. **Settings → Pages**：Source 選「Deploy from a branch」，分支 **`gh-pages`**、資料夾 **`/ (root)`**。（第一次推送後工作流程才會建立 `gh-pages`。）
2. **Settings → Actions → General**：Workflow permissions 選「Read and write permissions」。
3. **Settings → General → Pull Requests**：只勾「Allow merge commits」（不要用 squash／rebase，main 與 develop 的歷史才會一致）。
4. **Settings → Rules → Rulesets → New branch ruleset**（目標 `main`）：
   - Restrict deletions、Block force pushes
   - Require a pull request before merging
   - Require status checks to pass：`build-and-test`、`main-guard`
5. 另建一個 ruleset（目標 `develop`）：Restrict deletions、Block force pushes。

## 3. 發布（develop → main）

1. 在開發版網址確認要發布的內容都正常。
2. GitHub 開 PR：`develop` → `main`。
3. `checks` 自動執行：型別檢查、單元測試、建置，並確認來源分支與沒有影片檔。
4. 在 PR 頁面看過變更、檢查通過後，按「**Create a merge commit**」合併。
5. 合併後 `deploy-pages` 自動更新正式版網址。

## 4. 緊急修正（hotfix）

```powershell
git switch main
git pull
git switch -c hotfix/<名稱>
# 修正、commit
git push -u origin hotfix/<名稱>
# 在 GitHub 開 PR：hotfix/<名稱> → main，檢查通過後以 merge commit 合併
# 再把 main 合併回 develop，讓開發版也有這個修正
git switch develop
git pull
git merge origin/main
git push
```

## 5. 網站與素材

工作流程 `.github/workflows/deploy-pages.yml`：`main` 或 `develop` 有推送時自動建置，推送到 `gh-pages`。

```
gh-pages/
├─ index.html、js/            正式版（main）
├─ assets/ bgm/ voice/        正式版素材（只有 main 會改）
├─ .assets-hash               正式版素材版本
└─ develop/
   ├─ index.html、js/         開發版（develop）
   ├─ assets/manifest.json    開發版素材清單：相同的檔案指向 ../assets/，不同的指向 ./assets/
   ├─ assets/…                只有開發版才有、或內容不同的檔案
   ├─ voice/voice-index.json  同上（語音）
   ├─ bgm/                    開發版 BGM（約 36 MB，直接複製一份）
   └─ .assets-hash、.linked-main-hash
```

- 素材版本＝`遊戲素材/`、`自製素材/`、`game/tools/assets/build-assets.mjs` 的 git 雜湊；沒變就不重新轉檔（轉檔約 10 分鐘）。
- 開發版素材與正式版相同時不轉檔，清單全部指向正式版；不同時轉檔後由 `game/tools/deploy/link-develop-assets.mjs` 逐檔比對，只放入不同的檔案。
- 正式版素材更新後，工作流程會自動重新發布一次開發版，讓開發版的共用連結對到新檔案（期間只有開發版可能短暫缺圖，正式版不受影響）。
- Pages 網站上限約 1 GB；正式版素材約 630 MB，開發版只多出不同的檔案與 BGM。
- 開發版可用網址直接跳到某個畫面測試，例如 `/develop/#scene=tutorialBattle`（場景 id 見 `game/src/app/sceneRegistry.ts`）。正式版不支援。
- 直接把 Pages 指到 `main` 或 `develop` 分支是打不開的：那裡只有原始碼，遊戲需要先建置、素材要先轉檔。

## 6. 工作流程一覽

| 檔案 | 觸發 | 做什麼 |
|---|---|---|
| `deploy-pages.yml` | 推送到 `main`／`develop`、手動 | 建置並發布正式版或開發版 |
| `checks.yml` | 推送到 `develop`、PR、手動 | 型別檢查、單元測試、建置；併入 main 時檢查來源分支與沒有影片檔 |
